# PetVoice Lab

[在线体验](https://petvoice.xgc.ai/) · 在浏览器里用物理建模合成猫狗叫声。桌面左侧调嗓音，右侧选「叫」或「学说话」；手机上可以展开底部的「捏声音」。开启「调整后试听」，松开滑杆即可用新嗓音重播所选叫声或刚学的那句话。

| 控件 | 做什么 |
|---|---|
| **捏声音**（它是谁） | 选猫或狗、点一张预设图卡，再拖四个滑杆（个头、年纪、口鼻、嗓音）。也可以直接上手：**拖它的鼻子**改口鼻长短，**滚轮或双指缩放**改个头 |
| **叫**（心情和叫声） | 在心情轮盘上选 8 种心情之一，点叫声气泡（猫 11 种、狗 11 种）；点宠物本身也会叫，头顶会冒出拟声词 |
| **学说话** | 说一句、传一段或打一句，它用同样的语气叫出来；也可以切到“宠物自己叫”，让它学一段真实的叫声 |

顶栏只有三样：名字（点了就能改，不影响声音）、**透视**、**导出**。

- **宠物的外形**是一层圆润的外皮（耳朵、大眼睛、会眨眼，叫得响时眯眼），和里面的声道画在同一个三维
  骨架上：下巴挂在引擎算出的口腔底面上，所以张嘴是真实状态。平时声道隐约可见，**发声时会透过毛发
  亮起来**。外皮是代码画的扁平几何风格，毛色只是外观，不影响声音。
- **透视**打开后外皮变淡，露出完整的线框：声道是一串圆环（每个环是引擎的一段，粗细是它此刻的截面积），
  两片声带按声门开度左右分开，黄点是气流方向。同时滑杆旁的读数从“大块头”这类说法换成厘米和赫兹，
  角落里显示引擎的实际音高、延迟和负载。**引擎是一维的**：头的左右宽度、耳朵、眼睛只是画的。
- **导出**：当前叫声 WAV、全部叫声 ZIP、声纹卡片 PNG 和分享链接、对讲机那句的 WAV、竖屏短视频。
- “用它的真实叫声自动捏（实验）”在“捏”标签的底部；“循环放给宠物听”在“说”标签里。
- 拖动别处转头，双击回正；预设图卡上的头像由同一个渲染器按该预设的身体画出。

英文打字由合成人声念出来再模仿；中文打字按标点规则生成语调（没有人声）。

声音不是录音，也不是神经网络：是仿真气流在气管、声门、咽、口腔、鼻腔里的流动算出来的。声学引擎
直接复用 [CHIMERA](https://github.com/jamesondh/chimera-vocal-synth)（MIT）的 Rust 代码，编译成
92 KB 的 WASM，跑在 AudioWorklet 里（英文人声是另一个 558 KB 的模块，用到打字功能时才加载）。没有后端、没有大模型、没有遥测；首次加载后可离线使用。

> **先说最重要的一条限制：这一版的声音没有经过人耳验证。** 它是在一个没有音频输出的环境里
> 开发的，“像不像”只看过频谱图和数值指标（音高、脉冲率、电平、谐波结构）。验收标准第 1 条
> “听起来像这个物种”因此**尚未验证**，需要你们戴上耳机听一遍，见[已知不像的地方](#已知不像或可能不像的地方)。

## 运行

需要 Node 22+、Rust（带 `wasm32-unknown-unknown` 目标）。

```bash
rustup target add wasm32-unknown-unknown
```

```bash
npm install
```

```bash
npm run dev
```

`npm run dev` 先编译引擎再启动 Vite（http://127.0.0.1:5173）。AudioWorklet 和麦克风都需要安全上下文：
`localhost` 或 HTTPS。

| 命令 | 作用 |
|---|---|
| `npm run build` | 编译引擎、类型检查、打包到 `dist/`（纯静态文件，相对路径，可放任何静态托管的任意子路径） |
| `npm test` | 引擎和语音模块的 Rust 测试 + 参数层、听声捏回环、打字语调的自动检查（`scripts/test.ts`） |
| `npm run preview` 后 `npm run e2e` | 浏览器端到端测试：无头 Chromium + 假麦克风，截图存到 `out/` |
| `npm run render [预设id]` | 把每个预设的每种叫声渲染成 `out/*.wav` 和频谱图，调声音用 |
| `npm run bench` | 各预设的实时倍率 |

## 架构：参数层和发声层

```
┌─ 参数层（TypeScript，src/params，主线程，纯函数）──────────────────────────────┐
│ PetSpec（体型、年龄、口鼻、嗓音等）──bodyOf──▶ VoiceBody（14 个解剖数值：管长、截面积、声带…）    │
│                    └characterOf▶ VoiceCharacter（这只宠物怎么用嗓子）          │
│ 叫声名 / 人声韵律 / VoiceIntent ──▶ VoiceTrack（关键帧，每帧 14 个发声状态）     │
└───────────────────────────────┬───────────────────────────────────────────┘
                 只有 VoiceBody 和 VoiceTrack（两组 f64 数组）越过这条线
┌─ 发声层（Rust→WASM，engine/ + vendor/chimera，AudioWorklet）─────────────────┐
│ 帧 → 肺压、声门设置、各段截面积、管长、湍流噪声源 → CHIMERA 的 FDTD 气道 → 声音   │
│ 遥测（约 62 Hz）：各段截面积与声压、声门开度、气流、实际基频 → 主线程画剖面图      │
└───────────────────────────────────────────────────────────────────────────┘
```

- `src/params/protocol.ts` 是这条边界的全部定义，和 `engine/src/pet.rs` 的常量一一对应。
- 发声层不知道“猫”“撒娇”“问句”这些概念，只认数值。同一份引擎在 AudioWorklet（实时）、Web Worker
  （离线渲染卡片）和 Node（测试）里运行。
- 主线程不合成任何音频。卡片上的频谱是 Worker 里离线渲染的。
- 其他应用可以通过 `VoiceIntent` 指定心情、强度、时长和叫声（见 `src/params/intent.ts`）。

气道拓扑（CHIMERA 的 `mammal_airway`）：

```
肺（定压）→ 气管 → 声门 → 咽 ─┬─ 口腔 → 嘴唇（辐射）
                            └─ 软腭口 → 鼻腔 → 鼻孔（辐射）
```

## 参数是怎么映射到声道的

### 第一步的滑杆 → 解剖（`src/params/pet.ts`）

| 滑杆 | 改了什么 | 怎么改 |
|---|---|---|
| 物种 | 一组参考解剖 | 猫：声道 6.6–10.4 cm；狗：9–26 cm。各有一只参考个体的截面积和声带大小 |
| 体型 | 声道总长；所有截面积；声带面积；基频；肺压 | 声道长度在物种范围内线性插值；截面积 ∝ 长度²；基频 ∝ 长度^−1（猫）/ ^−1.25（狗） |
| 年龄 | 声道长度（幼崽约为成年的 52%）、声带、基频 | 0–0.42 为生长期：长度按生长曲线缩放，基频 ∝ (1/生长系数)^1.1；0.6 以后声带变厚 25%、基频降 16%、多一点粗糙和气泡音 |
| 口鼻 | 声道总长；口腔占声道的比例；鼻腔粗细；口腔粗细 | 声道长度 ×0.88（扁脸）→×1.12（长鼻）；口腔占比 猫 54%→68%、狗 52%→72%；鼻腔截面 ×0.45→×1.25；长口鼻的口腔略窄 |
| 质地 | 声带闭合、气声、不规则振动 | 清亮：张力 +0.25、气声 −0.08；沙哑：气声 +0.22、粗糙 +0.4·x²、气泡音 +0.25·x² |
| 情绪（8 种） | 肺压、声带张力、气声、粗糙、软腭、张嘴幅度、基频、节奏 | 撒娇：压 ×0.82、基频 ×1.12、鼻音重、略带气声；开心：张力 +0.1、节奏 ×1.2；好奇：基频 ×1.2、压 ×0.72、节奏 ×1.35、嘴张得小；兴奋：压 ×1.3、基频 ×1.15、节奏 ×1.45；委屈：压 ×0.8、气声 +0.14、颤音 45 音分、节奏 ×0.78；害怕：基频 ×1.32、压 ×0.78、气声 +0.28、颤音 110 音分；困倦：压 ×0.65、基频 ×0.88、气泡音 +0.2、节奏 ×0.65；生气：压 ×1.7、张力 +0.22、粗糙 +0.38、基频 ×0.8 |

### 每一帧的 14 个发声状态 → 物理量（`engine/src/pet.rs`）

| 帧字段 | 物理量 |
|---|---|
| `f0` | 声带被“拉”到的音高：双质量声带模型的弹簧变硬、参与振动的质量变小，自激振荡落在这个频率附近（有慢反馈校正）。90 Hz 以下（呼噜）仍是 25 Hz 左右的规定脉冲 |
| `pressure` | 肺的定压（cmH₂O）。负值是吸气（呼噜的吸气相） |
| `jaw` | 嘴唇段的截面积（0 时完全封闭，声音只能走鼻腔）和口腔前部的楔形张开 |
| `round` | 嘴唇截面积缩小到 20%，口腔管长 +14% |
| `tonguePos` / `tongueHeight` | 声道上一处高斯形收窄的位置和程度，别处相应变宽 |
| `tension` | 两片声带静止时靠得多紧（静止开度变小直至压紧），闭合更实、谐波更多 |
| `breath` | 声带静止开度加大、气息噪声加重；约 0.8 以上气流吹不动声带，自己停振（哈气、喘气） |
| `rough` | 左右两片声带调得不一样（一片紧 20%、一片松 50%，按比例），再加气流对声带的随机扰动；倍周期、破音、不规则都是振荡自己出来的 |
| `fry` | 高于 90 Hz 时并入左右失谐；呼噜段仍是低频双脉冲 |
| `hiss` | 口腔最窄处的湍流噪声源增益（噪声强度仍由该处气流的雷诺数决定） |
| `pulseDepth` | 肺压约 25 Hz 的周期性调制的深度（咕噜叫） |
| `vibrato` | 基频颤动，音分 |
| `larynx` | 咽管长 +25%、截面 +30%（喉头下降） |

叫声本身（`src/params/calls.ts`）是这些状态的关键帧。比如“喵”就是 m–e–a–o–u：闭唇鼻音起音 →
舌前高、唇微开 → 下颌大开、基频到顶 → 圆唇、舌后缩 → 合拢。“汪”是在憋足气的圆唇后面突然张嘴，
同时把 `rough` 推高。呼噜是 25 Hz 左右的声门脉冲，呼气和吸气两相都有。

叫声清单：猫——喵、咪、吱、咕噜叫、过来、咔咔叫、呼噜、哈气、低吼、嚎叫、叫春；狗——汪、吠吠、闷吠、猎吠、
长嚎、哼唧、呜咽、尖叫、低吼、喘气、叹气。

### 第二步：人声韵律 → 叫声（`src/analysis/`、`src/params/prosody.ts`）

- 降采样到 16 kHz，10 ms 一帧；音高用 YIN（65–520 Hz），音量用 RMS。
- 清理：倍频错误折回中位数附近、5 点中值、去掉短于 30 ms 的有声孤岛；音量包络找停顿和音节。
- 音高映射：`宠物音高 = 宠物基频 × 2^(k × 相对你自己中位音高的半音数 / 12)`，k = 1.7（猫）/ 1.5（狗），
  夹在宠物的音域内。所以曲线形状不变、幅度被拉大，问句尾音上扬在叫声里也上扬。
- 音量 → 肺压和张嘴幅度；停顿 → 断气；音节 → 嘴的开合。猫把一个短语叫成一声长喵（每个音节张一次嘴），
  狗把每个音节叫成一声“呜/汪”（短促的音节更粗糙）。
- 清辅音处的音高缺口按对数频率插值补上：宠物不会说悄悄话。

### “宠物自己叫”模式（`analysePetProsody`、`prosodyToTrack` 的 `fromPet`）

对讲机顶部的“录的是：人说话 / 宠物自己叫”切到后者时，录音和上传的处理不同：

- 麦克风关掉语音降噪和自动增益；音高在 55–2600 Hz 里找，用频谱谐波梳而不是 YIN（猫的基频常常比二次
  谐波弱），不做“往中位数折八度”。
- 音高**按原样照搬**（不拉伸），只把整段移到你捏的这只的音高上；录音里不干净的帧会叫得更粗糙；
  整段都没有音高的（哈气、喘气）改用纯气息。
- “原声”按钮播放录音本身，可以和合成的前后对比。

验证（只用本应用自己合成的叫声，**没有真实录音**）：合成猫的喵、叫春和狗的哼唧、长嚎，只凭音频分析，
再让另一只体型不同的同类学一遍，引擎实际的音高曲线和原曲线相关度 0.98–1.00，中位音高落在模仿者
自己的音高上（`npm test`）。长嚎的音域会被模仿者的音域上限压窄（21 → 15 个半音）。吠叫、低吼这类
粗糙叫声的音高本来就提不准，没有列入测试。

### 打字（`speech/`、`src/params/textprosody.ts`）

- **英文**：用 CHIMERA 自带的人声（文字→音素→发音动作→同一套声道物理），在 Worker 里离线合成一段
  听得见的机器人声，再走和录音完全一样的分析链路。问句、陈述句的语调来自 CHIMERA 的规划器。
  发音词典是 CMUdict（870 KB，随页面分发，首次打字时加载；加载不了就退回按字母拼读）。
- **中文（或任何含汉字的文本）**：本地没有中文语音合成，所以**不合成人声**，直接按规则写一条语调：
  一个汉字一个音节，短语内音高缓降，句号下降、问号上扬、感叹号整体抬高加重，结尾是“吗/么/呢”
  也算问句。不含四声、重音和语义，“原声”按钮不可用。

### 听声捏：从真实叫声反推滑杆（`src/analysis/petsound.ts`、`src/params/fit.ts`）

1. 量音高：频谱谐波梳（比 YIN 更不容易被二次谐波带偏）。
2. 量声道长度：一端闭一端开的管在 (2k−1)·c/4L 处共振、k·c/2L 处是谷。把长时平均谱的包络和
   3–32 cm 每个长度的“共振梳”比对，取最吻合的几个候选。
3. 量质地：谐噪比。
4. 用参数层自己的正向模型在（体型, 年龄）网格上搜索，找出声道长度和音高都对得上的滑杆。

用户要先选“这段是哪种叫声”，因为不同叫声的音高和招牌音高的比例不同。支持：猫——喵、咪、嚎叫、
呼噜、低吼；狗——汪、闷吠、长嚎、低吼。

**验证方式和结果（只是自洽性，不是真实动物）**：用本应用合成 5 只已知参数的宠物、每种支持的叫声各
一段，量、反推、再比较。声道长度最坏误差 1–8%，音高最坏误差 0.2–1.7 个半音（`npm test`）。
猎吠、哼唧、叫春、呜咽在同样的测试里误差超标（最坏 20–58%），所以没有放进可选列表。

**要知道的限制**：
- **年龄听不出来。** 在这个模型里，幼崽和小个子成年如果声道一样长，音高也几乎一样（音高近似只是
  声道长度的函数）。所以年龄保持用户设的值，只有在该年龄下怎么调体型都够不到测量值时才动。
- **口鼻听不出来**，不动。质地只能粗分清亮/沙哑，而且只在喵、咪、汪上估。
- **没有用任何真实猫狗录音验证过。** 模型的共振峰本身没有对照真实动物校准，真实录音里还有混响、
  噪声和人声。真实效果未知，这个功能目前应当看作实验。

软腭不在这 14 项里：它由引擎跟着嘴唇走（闭嘴时全开，声音从鼻子出去；张嘴后基本关上）。

## 对着真实录音校准

有人听过之后反馈“和真实的叫声有差距”，于是做了一轮有数据依据的校准（`scripts/realcal.ts`、
`scripts/features.ts`）。

- **参照**：68 段真实的猫叫和狗吠（猫 29 段、狗 39 段），来自 ESC-50 数据集里单条授权为 CC0 或 CC BY 的
  片段，切出 78 声猫叫、180 声狗吠。来源和作者见 `docs/reference-recordings.md`。**音频不在仓库里**，
  只用来测量。
- **量法**：真实叫声和我们的喵 / 汪用同一套特征：时长、起音和收尾时间、音高和它的起伏、抖动、谐噪比、
  频谱重心和倾斜、24 段频谱形状。偏差用“真实数据的四分位距”作单位。
- **改了什么**：
  - 喵：缩短（约 0.75 → 0.55 秒）、起音更快、音高起伏从约 4 个半音压到 1–2 个；
  - 汪：音高几乎不滑；狗的声带改成更“压紧”、少漏气；
  - 声带加了一层随气流起伏的气息噪声（原来的湍流源在宠物这么小的声门上基本不启动，所以合成的声音
    比任何真实叫声都“干净”）；
  - 音高抖动减半；喉上段不再收得那么窄（原来在 3–4 kHz 有一个真实叫声里没有的共鸣）；
  - 输出端加了一个 4.2 kHz 的两极点低通，代表宠物到录音之间的空气和话筒。

| 谐噪比（dB） | 7.1 | 30.2 | 18.3 | 8.8 | 10.0 | 11.6 |
| 频谱倾斜（dB/倍频程） | −5.7 | −5.0 | −5.7 | −12.6 | −7.8 | −8.3 |
| 综合偏差分（越低越近） | — | 11.4 | 3.9 | — | 8.0 | 6.0 |

### 换成自激振荡的声带之后

声源从“规定好形状的声门面积脉冲”换成了双质量声带模型（`engine/src/folds.rs`，Ishizaka–Flanagan 的
双质量结构，气动力和左右不对称按 Steinecke–Herzel 1995）：每片声带是上下两个质量块加弹簧，气压把它们
推开，弹簧和碰撞把它们拉回，开合的波形和周期都是算出来的，不再是画出来的。声道的压力反过来作用在
声带上。人的参数按线度缩放到猫狗的声带大小。

| | 猫：喵 | | 狗：汪 | |
|---|---|---|---|---|
| 特征 | 规定脉冲 | 自激声带 | 规定脉冲 | 自激声带 |
| 谐噪比（dB，真实 7.1 / 8.8） | 18.3 | 20.8 | 11.6 | 11.0 |
| 频谱倾斜（dB/倍频程，真实 −5.7 / −12.6） | −5.7 | −7.0 | −8.3 | −9.6 |
| 综合偏差分 | 3.9 | 4.5 | 6.0 | 5.7 |

如实说：**数值上基本打平**，狗吠略近（倾斜好了 1.3 dB，离真实仍差 3 dB），猫叫略远（更干净、基频更突出）。
换模型的理由不在这张表，而在机理：粗糙感现在是两片声带失谐后自己破出来的，不是混沌映射；气压不够或
声带张太开时会自己不响；音高会被声道共鸣拉偏。这些听起来是否更像，要人来听。

有三处不是纯物理，写明：
- 音高靠“目标频率 → 弹簧/质量”的换算加慢反馈锁定，真实动物靠肌肉；
- 升高音高时 1/4 靠弹簧变硬、3/4 靠振动质量变小（纯靠变硬的话，猫叫的音高需要大得不合理的气压才能起振）；
- 呼噜（约 25 Hz）不是气流吹出来的，是喉肌主动抽动，所以 90 Hz 以下仍用原来的规定脉冲。

副作用：很沙哑的狗叫现在真的没有稳定音高，“听声捏”遇到谐噪比低于 4 dB 的吠叫会直说读不出来，只调音色。

**还没对上的**：
- **狗吠仍然偏亮、中频不够厚**：真实吠叫的能量集中在 400–1700 Hz，往上掉得很快（−12.6 dB/倍频程），
  换成自激声带后做到 −9.6，仍差 3 dB。剩下的差距多半在声道形状和辐射上，不在声源。
- 猫的谐噪比仍比录音高约 14 dB。录音里有环境噪声，没有硬追。
- **只校准了喵和汪**。数据集里几乎全是这两种，其余叫声只是跟着全局改动一起变了，没有各自的参照（“过来”例外：它的音高走向量自一段人模仿的教学视频，见 `docs/reference-recordings.md`）。
- 录音里的动物体型、距离、话筒都未知，录音本身带房间声，所以这是“往真实的分布靠”，不是逐只对齐。
- 这是数值上的接近。**好不好听仍然要人来听**，校准后的版本还没有人听过。

## 消融实验：每个部件到底有没有用

`npx tsx scripts/ablate.ts` 逐项关掉或拉动一个部件，离线渲染前后两段声音，量 40 段对数频谱的平均差
（dB，两段都先归一化电平、拉伸到同样长度）。经验上 1 dB 以下听不出，3 dB 以上是明显不同的声音。
**它量的是“声音变了多少”，不是“变得对不对”。**

| 对象 | 结果 | 据此做了什么 |
|---|---|---|
| 帧字段 `velum`（软腭） | 单独变化最多 1.0–1.1 dB | 从接口里去掉，改为引擎随嘴唇自动开合 |
| 帧字段 `pulseRate`（脉冲频率） | 最多 0.7–1.1 dB | 去掉，固定 25 Hz |
| 其余 12 个字段 | 各自至少在一种叫声里超过 1.5 dB（`jaw`、`breath` 最大，5–15 dB） | 保留 |
| 滑杆：体型、年龄 | 5–15 dB | 保留 |
| 滑杆：质地 | 喵 6.4、汪 3.7 dB；对呼噜和哈气为 0（它们不走常规声带振动） | 保留 |
| 滑杆：口鼻 | 原来猫只有 1.5–1.9 dB | 让长口鼻同时加长声道（解剖上本来如此），现在 2.4–4.3 dB |
| 情绪：兴奋≈害怕、撒娇≈好奇 | 原来最近的两对只差 2.2–2.9 dB | 把好奇改成更轻更短更高、害怕改成气弱发抖；猫最近的一对现在差 5.1 dB。**狗的“好奇–兴奋”在吠叫上仍只差约 2–3 dB** |
| 叫声 | 同物种内最接近的一对也差 6.7 dB | 全部保留 |

界面上同时去掉的：视角按钮（改为拖动 + 双击复位）、舞台上重复的参数读数、卡片弹窗里的试听按钮、
“对着宠物播放”里的间隔选择和反应记录（只留一个循环开关和提示）、页头的性能读数（移到页脚）。
代码里去掉的：没人读的音频分析节点、被取代的脚本、两段没用到的测试音频。

## 哪些参数是凭经验调的

**几乎全部。** 物理来自 CHIMERA；这只是把它调成猫和狗的那一层，没有一项是从动物身上测出来的：

- 物种的声道长度范围、参考截面积、声带面积、气管长度（`ANATOMY`）。量级参照了常见的文献数字，
  但没有逐项核对出处，请当作估计值。
- 基频随体型和年龄变化的指数；幼崽的生长曲线。
- 四种情绪和“质地”对肺压、张力、气声、粗糙的全部系数。
- 全部 22 种叫声的关键帧形状和时长；8 种情绪的系数。其中喵和汪的时长、起音、音高起伏，以及猫狗的
  声带松紧、气息噪声、话筒低通，是对着真实录音调的（见“对着真实录音校准”），其余仍是凭经验。
- 听声捏里各叫声的音高比例、声道长度偏差系数（猫 1.02、狗 1.06）、谐噪比到质地的阈值：都是对着
  本应用自己的合成结果定的。
- 中文打字的语调规则。
- 面积函数的形状：均匀管 + 一个高斯形舌位 + 楔形下颌 + 窄的喉上段。不是解剖扫描数据。
- 音高拉伸系数 1.7 / 1.5。
- 音量：按体型拟合的输出增益（`scripts/calibrate-gain.ts`）；小体型的噪声补偿；呼噜 ×9、低吼 ×1.6
  的“话筒靠近”增益；引擎输出端 3:1 的电平压缩。这些都是音量旋钮，不是物理。

## 已知不像（或可能不像）的地方

没有人耳验证过，下面是从频谱、数值和模型结构能判断出的问题：

- **小奶猫的哈气几乎没有声音。** 噪声由雷诺数驱动，这么小的声道气流量过不了湍流阈值。
- **呼噜的相对音量是假的。** 物理上它比喵低约 40 dB，靠 ×9 增益和压缩才听得见。脉冲率是对的
  （实测 23–29 Hz，呼气吸气两相都有，`scripts/purrcheck.ts`）。
- **声带是人的双质量模型按比例缩小的**，不是照猫狗的喉部测的；猫的声带垫、狗的喉室都没有建模。
  粗糙的叫声音高会偏离设定值（两片声带失谐后锁到哪一片不固定），这是模型的真实行为，不是故障。
- **共振峰没有对照真实录音校准。** 第一共振峰只按“一端闭一端开的管”估算（猫约 1 kHz，大狗约 340 Hz）。
- **扁脸**只改了鼻腔粗细和口腔占比，没有模拟软腭过长等造成的鼾声。
- **声音很干**：没有混响和话筒模型。
- **小奶猫的声道在 96 kHz 下只有约 10 段**，面积函数很粗。
- **喘气**是纯噪声交替吹吸，没有舌头的湿润感。
- 只做猫和狗。
- 新加的 9 种叫声和 4 种情绪只检查过能出声、电平正常，频谱都没有逐个细看。
- 导出文件名带中文宠物名时，测试用的无头浏览器会把文件名报成 `download`；真实浏览器里是否正常没有
  验证过（英文名正常）。
- 对讲机：耳语和噪声里的话没有音高，会被拒绝；嘈杂环境、多人同时说话没有处理；音节检测只看音量包络。

## 性能和兼容性

- 引擎内部采样率：声道短于 12 cm 的用 96 kHz（一段管不能短于 声速/采样率），更长的用 48 kHz。
- 开发机（一台慢的 4 核云主机）上 WASM 的单核负载：小奶猫 12%，成年猫 22–28%，小型犬 33%，
  中型犬 12%，大型犬 17%。负载持续超过 80% 时引擎自动切到“省电模式”（全部用 48 kHz）。
- **只在桌面 Chromium（无头）里实际跑过。iOS Safari 和 Android Chrome 没有真机测试。** 代码按它们的
  限制写了（首次点击后才创建 AudioContext；WASM 以字节传进 Worklet 同步编译；视频优先 H.264 MP4，
  没有就用 WebM；手机视口测过布局），但请上真机验证，尤其是 iOS 的 MediaRecorder 和麦克风。
- 导出视频是实时录制的，录制期间 CPU 占用会明显升高。

## 部署

- `npm run build` 产出的 `dist/` 是纯静态文件（约 1.8 MB，其中英文人声模块和发音词典 1.4 MB，按需加载），资源用相对路径，放到任何 HTTPS 静态托管的
  任意子路径即可（GitHub Pages、Vercel、Cloudflare Pages、对象存储）。
- 演示站部署在 Cloudflare Workers 静态资源托管上。[体验 PetVoice Lab](https://petvoice.xgc.ai/)
- 自行部署到 Cloudflare 时，请将 `wrangler.jsonc` 里的域名改为自己的域名。录音需要 HTTPS 或 localhost，并由浏览器申请麦克风权限。
